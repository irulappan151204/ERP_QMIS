ERP Master Overview – QMIS
Version 0.1. Consolidates the seven department documents (Academics, Non-Academics,
HR, Finance, Audit, MD, Admin). Use this as the master reference for design and build.
Items marked [Proposed] are my suggestions.
1. System Summary
One centralised, dynamic ERP for the whole school. Every department, role and module is
connected, so data entered once is visible to the right people everywhere. Key principles:
Role-based access: each user sees only what their role allows; higher ranks see the
data of those below them; the MD sees everything.
Approval hierarchy: requests move up a defined chain; approval limits are set by
Finance.
Immutable records: nobody can edit or delete saved data, including Admin and MD.
History is permanent.
Everything is audited: logins, entries, downloads and prints are logged for the MD and
JD Audit.
Automation first: attendance from RFID, fee bills on WhatsApp, reminders, escalations
and user creation happen automatically.

3. User Lifecycle
User Information System (UIS): a lifetime record for every user (student from Grade 1 to
10 and beyond; staff from joining to exit) with profile, documents, achievements,
activities, marks, attendance, fees and concessions, transport, complaints, disciplinary
records and sibling information. It is the backbone that every department reads from.

6. End-to-End Cross-Department Flows
6.1 Admission to student user
Enquiry (PRM) → campus visit → request form → admission → payment in Finance →
student user created automatically → temporary password email → profile in UIS → class
assignment → fee schedule, transport and activity fees.
6.2 Daily attendance
RFID punch (iClock) → sync to ERP → no punch = absent → leave/permission auto-marks →
Class Teacher / Dept Head confirms or time limit finalises → parent message → payroll and
audit read the result.
6.3 Staff leave
Staff requests → Dept Head + HR approve → attendance updates to Leave → if emergency,
Principal/DA reassigns periods (Academics) or the head reassigns duty (Non-Academics)
→ payroll uses the result.
6.4 Lesson plan to publication
Teacher creates monthly plan (by the 25th, reminder 7 days before) → Coordinator →
Principal → DA approve → published to timetable users → audited monthly.

6.5 Exam and marks
Principal creates exam timetable → DA approves → notification → teachers upload
question banks → marks entered (single or bulk) → Coordinator → Principal → DA approve
→ results published → student/parent view → analytics and audit.
6.6 Store request and purchase
User views stock → raises request → head/DA/Principal approves (Finance limit) → Store
issues (returnable / non-returnable marked) → if not in stock → purchase requirement →
Store Officer compares vendors → approval → budget check → PO → goods received →
owning department confirms → stock added → Finance voucher and payment.
6.7 Ticket (repair / cleaning / IT)
User raises ticket to a department → assigned person → resolved → requester confirms →
unresolved/not satisfied → next higher rank → history retained.
6.8 Gate pass
Request by PRM or user (approvers chosen by the requester) → class teacher and chosen
higher ranks approve → pass generated → Security verifies → gate log recorded.
6.9 Complaint
User raises complaint → receiver acts within 24 hours → no solution or no reply →
automatic escalation up the chain (up to the MD) → or the user clicks Not Satisfied →
escalates → full history kept.
6.10 Fee payment
Fee structure by class → reminders → payment (counter, online, Paytm POS) → receipt →
WhatsApp bill → profile updates paid/pending → books post automatically → transport
and activity data sync.
6.11 Payroll
Attendance, leave, deductions, incentives (extra work time per hour, referrals), advances
and loans → payroll by HR → payslip → Finance voucher and bank payment → books.
6.12 Transfer Certificate (TC)
Student requests with description → Class Teacher → Coordinator → Principal → DA →
department NOCs (Transport, Library, Finance dues and others) → MD final approval →
TC generated.

6.13 Staff recruitment to onboarding
Vacancy → recruitment → interview (panel from another department, feedback and
ratings) → offer letter → HR enters staff → user created → onboarding checklist across
departments → shadow mentor and observation → confirmation.
6.14 CCTV footage and file access
Camera Room marks and stores footage on issues; any Department Head can request
footage → approval (sensitive cases up to the MD) → released and logged. Files carry a
per-file confidentiality list set at upload; access is approved by the designated authority.
6.15 Transport trip
Transport Manager configures routes, trip start/end, student list and fee status (from
Finance) → driver/conductor onboard/offboard screen per trip (home or school pickup) →
GPS live location → parent view in student profile → audit checks GPS and issues.
6.16 Audit and corrective action
Audit plan generates tasks → auditors fill checklists with evidence → findings rated →
corrective action assigned with owner and deadline → closure verified → scores to BSC →
reports to the MD.
