ERP Documentation – 7. Admin (ERP Super
Admin)
Version 0.1 (draft). Admin is the ERP super admin: it is not an inter-department team. It
configures and controls the ERP itself. Items marked [Proposed] are my suggestions for
you to confirm.
1. Purpose and Scope
Admin is the super admin of the ERP. It does not run a school department and has no
inter-department workflows. Its job is to set up, configure, secure and maintain the
system so every department can work.
Admin owns: system configuration, roles and permissions, master data, integrations,
notification rules, security settings, backups and system health.
Admin does not: create staff users (HR does), approve business requests, or enter
academic, finance or HR data.
Global rule: the no-edit and no-delete principle applies to business data for Admin too.
Admin can configure the system and correct system settings, but cannot alter or remove
records such as marks, fees, attendance or HR entries [Proposed].
2. Roles
If you want a single Super Admin only, the assistant role can be removed.
Difference from IT Support (Non-Academics): IT Support (System Admin in the Non-
Academics list) handles tickets, devices, network and hardware. The ERP Super Admin
handles the application configuration. They may be the same person or different people;
the permissions stay separate.
Role Responsibility
Super Admin Full system configuration and control (this
document).
Admin (assistant) [Proposed] Limited configuration tasks delegated by the Super
Admin, such as master data and notification
templates.

8.2 Recommendations (you asked me to suggest)
4. Multiple campuses: build for it now, run one campus today.
Recommendation: design the ERP as multi-campus ready from day one, even if only one
campus is active.
Every record carries a campus tag; today it is the single campus.
Adding a new campus later is then a configuration step (new departments, classes, fee
structure, staff), not a rebuild.
The MD sees all campuses together and can filter by campus. Each campus can have
its own Principal, Department Heads and Store.
Why now: adding campus separation afterwards means changing every table and
every report, which is expensive. Doing it at the start costs little.
5. Password change policy: do not force a change every 15 days.
Recommendation:
In the ERP every user has their own login, so the fortnightly change in the Audit SOP
(shared logins in the control room) is not needed.
Frequent forced changes make users choose weak, predictable passwords. Current
security guidance favours long passwords, lockout after failed attempts and extra
verification over frequent rotation.
Default setting: change on first login (temporary password), then every 90 days,
adjustable in settings.
Two-step verification (OTP) switched on for high-risk roles: MD, Finance Head,
Finance Assistant, HR, Super Admin and Assistant Admin.
Immediate forced change if a password is reset by Admin or suspected leaked.
The Audit plan item "Login password change (day 1 and 16)" becomes a check that the
policy is working, not a manual task.
